# Incident Investigation 002 — Privileged Local Group Membership Change

## Scenario

A detection reports that an account was added to the local Windows Administrators group.

The investigation objective is to determine:

- who performed the change
- which account was added
- whether the account is actually present in the Administrators group
- whether a real Event ID 4732 exists
- whether surrounding authentication activity supports a real privilege change
- whether the alert should be treated as malicious, benign, or synthetic test activity

## Safety Approach

This investigation intentionally avoids making a real privileged-group change.

The positive alert is generated using the detector's safe `-TestMode`, which simulates an Event ID 4732-style record through the same detection logic.

The investigation then verifies the real endpoint state and Security logs.

## Primary Evidence Sources

- Detector output from `detect_admin_group_addition.ps1 -TestMode`
- Windows Security Event ID 4732
- Windows Security Event IDs 4624 and 4625
- Current local Administrators group membership

## Investigation Helper

`scripts/collect_admin_group_investigation.ps1`

The helper:

1. enumerates current local Administrators membership
2. searches for recent Event ID 4732 records
3. reviews recent successful and failed logons
4. provides endpoint context for the alert

## Planned Workflow

1. Run the synthetic privileged-group detector.
2. Record the actor, member, host, and target group.
3. Collect current Administrators membership.
4. Search for real Event ID 4732 records.
5. Review nearby 4624/4625 authentication activity.
6. Compare the alert with actual endpoint state.
7. Determine scope and disposition.
8. Document remediation and lessons learned.

## Expected Outcome

Because the alert is intentionally synthetic and no real group membership is changed, the likely disposition is:

```text
Benign Positive / Synthetic Test
```

The important analyst task is proving that conclusion from endpoint evidence rather than assuming it.


## Investigation Results

The detector was run in safe synthetic validation mode and produced:

```text
ALERT: Account added to privileged local group.
Time: 09/19/2026 20:09:07
EventId: 4732
Computer: ED_T14
Actor: Ed_T14\\ej975
MemberName: LAB\\testuser
MemberSid: S-1-5-21-111111111-222222222-333333333-1001
TargetGroup: Builtin\\Administrators
ValidationMode: Synthetic
```

The endpoint investigation collector then verified the real system state.

### Current Local Administrators Membership

Observed members:

```text
Ed_T14\Administrator
ED_T14\ej975
```

The synthetic account `LAB\testuser` was **not** present in the actual local Administrators group.

### Windows Security Event ID 4732

No real Event ID 4732 records were found in the previous 30 minutes:

```text
No Event ID 4732 records found in the last 30 minutes.
```

This is strong evidence that no actual local-group membership change occurred during the investigation window.

### Surrounding Authentication Activity

Recent Security log activity included successful Event ID 4624 logons for:

```text
NT AUTHORITY\SYSTEM
LogonType: 5
ProcessName: C:\Windows\System32\services.exe
```

These are service logons and did not indicate that `LAB\testuser` authenticated or received privileged access.

The alert claimed:

```text
LAB\testuser -> Builtin\Administrators
```

but endpoint evidence showed:

```text
No LAB\testuser membership
No real Event ID 4732
No related interactive authentication
```

The detector's `ValidationMode: Synthetic` field also directly identified the alert as test activity.

## Scope

Observed scope was limited to the lab detector test.

- **Host:** ED_T14
- **Actor in synthetic event:** Ed_T14\ej975
- **Synthetic member:** LAB\testuser
- **Target group:** Builtin\Administrators
- **Real privileged membership change:** None observed
- **Related suspicious logon activity:** None observed

| Technique | ID | Evidence |
| --- | --- | --- |

Because no real account manipulation occurred, this ATT&CK mapping describes the behavior simulated by the detection rather than actual malicious activity on the endpoint.

## Assessment

- **Final Severity:** Informational
- **Disposition:** Benign Positive / Synthetic Test
- **Confidence:** High

### Rationale

The alert was intentionally generated through the detector's synthetic validation mode.

Independent endpoint verification showed:

- the test account was not present in the Administrators group
- no real Event ID 4732 was recorded
- no related authentication activity indicated the synthetic account obtained access
- current privileged-group membership remained unchanged

This confirms the alert represented test activity rather than a real privilege escalation or persistence event.

## Recommended Response / Remediation

Because this was a controlled lab test:

- no containment action is required
- retain the evidence as a training case
- keep the Event ID 4732 detection enabled
- in production, correlate future alerts with actual group membership and change-management records
- investigate actor account, member account, nearby logons, and process activity before closing a real alert

## Lessons Learned

1. A detection alert should be validated against the actual endpoint state.
2. Security Event ID 4732 is a strong source for confirming local-group membership changes.
3. Current group membership helps determine whether the reported change persists.
4. Authentication events provide supporting context but should not be interpreted in isolation.
5. A clearly labeled synthetic test can validate detection logic without making a risky real privilege change.
6. SOC analysts should prove why an alert is benign instead of assuming it from the test context.
